> 目标：给 10 件 Zenodo RPTU 锚点零件补上**面级语义标签 + 特征实例标签**，
> 补上 MFCAD++ 只有语义、没有实例的缺口，也让 M2 的零样本评测有一个真值基准。

## 1. 怎么补：四步流水线

```
STEP ──(FreeCAD worker)──> 面表+三角剖分 ──> 八视图/逐面高亮 ──> 规则预标注 ──> 人工判读覆盖 ──> 最终 JSON
         geom_worker.py        geom/<n>.json     render.py        autolabel.py    overrides/<n>.json   finalize.py
```

一键跑：

```bash
python scripts/annotate/build.py        # 几何抽取 + 渲染 + 规则草稿（10 件 < 2 分钟）
python scripts/annotate/finalize.py     # 草稿 + 人工覆盖 -> data/zenodo_rptu/labels/<n>.json
python scripts/annotate/check.py        # 自洽性 + G 代码交叉对照
python scripts/annotate/review.py       # 生成 reports/annotation/review.html
```

### 1.1 为什么自己渲染，不用 FreeCAD 截图

headless 下 coin 渲染依赖 GL 上下文，在这台机器上不可靠；更关键的是**要可寻址的面号**。
按 STEP 的面顺序投影 + 画家算法排序，图上每个数字就是 JSON 里的 `index`，
判读结果可以直接回写，不需要任何几何匹配（同面积面做几何匹配必然歧义）。

两个踩过的坑写在代码注释里：
- 面号遮挡判定不能拿"面平均深度"和"该点最近深度"比大小 —— 斜视图下同一个平面跨越大范围深度，
  必须比较**面 id**（该点最近的那片三角形是谁的）。
- 逐面高亮图不能纯正视图，否则看不出"这是哪一侧"；用"法向 + 斜向偏移"的视角才既有正面可判读性又保留邻面。

### 1.2 规则预标注的三条规则

1. **stock 面**：平面 ∧ 轴向法向 ∧ 面所在平面与包围盒某面重合。
   不用"沿凸边洪泛"（槽口与顶面是凸边，会把槽壁吞进 stock，件 1 实测 0 特征）；
   也不用"任意触到包围盒的面"（外轮廓圆角的 bbox 同样触到包围盒，会被误判成 stock）。
2. **实例分组**：stock 之外的面按共享边求连通分量。这一步直接产出实例标签 ——
   MFCAD++ 做不到的事。
3. **判类**：圆柱看切向边（≥1 条 = 圆角）、法向朝轴心与否（孔）、是否通到底面；
   平面看底面/侧壁数量与"是否破出包围盒"（通槽 vs 盲槽 vs 型腔 vs 台阶）。

### 1.3 人工判读做什么

规则在真实件上只对了一半（见报告 §3），人的活是三件：
- **纠错**：规则把 Ø70 圆柱凸台判成"孔"（半径 35 也是"法向朝轴心"），肉眼一秒否掉。
- **拆合**：规则把整件 8 的台阶+斜面+凸台粘成一个分量；人按 G 代码工序拆成 3 个 step + 2 个 boss。
- **加类**：真实件的凸台（boss）、让位槽、方变圆过渡、腔内岛在 MFCAD 25 类里**没有对应类**，
  必须扩一个 `boss` 家族并允许 `mfcad_class = null`，否则只能瞎凑一个类名。

## 2. 标注口径

```jsonc
{
  "part": "7", "n_faces": 17,
  "taxonomy": "family(9) + mfcad_class(25, 可为 null)",
  "faces": {                      // 每个面有且只有一个归属
    "3": {"family": "pocket", "mfcad_class": null, "feature": "F1"},
    "12": {"family": "stock", "mfcad_class": "stock", "feature": null}
  },
  "features": [                   // 实例级
    {"id": "F1", "family": "pocket", "mfcad_class": null,
     "faces": [3, 5, 7, 8, 10], "note": "自由轮廓盲腔，深 10", "reviewed": true}
  ],
  "stock_faces": [12, 13, 14, 15, 16, 17],
  "review_needed": false, "open_questions": []
}
```

家族（9 类）：`stock / hole / pocket / slot / step / boss / fillet / chamfer / freeform`。
注：这是通用分类体系；本批 10 个零件的 `labels/*.json` 实际只用到 **7 类**，
`chamfer` / `freeform` 无实例。6 个 `BSplineSurface` 面按所属特征归 `boss`，不按面型归 `freeform`
（与 M2「BSpline 面训练集不存在必然误判」一致）。人工标注的规则优先级见 `docs/STUDY-TRAINING.md` 规则 0。
`mfcad_class` 只在**能明确对上 MFCAD 25 类**时填，对不上就 `null` 并在 `note` 里写清是什么 ——
硬凑一个类名会让后面的评测数字失去意义。

### 2.1 圆柱面先算两个数，再判类

圆柱面（`Cylinder`）是这批件里最容易判错的面型——圆角、孔、销、沉孔壁全长一个样。判之前先算：

| 量 | 算法 | 用途 |
|---|---|---|
| **弧段占比** | `面积 / (2πRh)`，h 取面 bbox 的 z 跨度 | ≈0.25 → 拐角圆角；≈1.0 → 整圆柱（孔/销/沉孔壁） |
| **法向·径向** | 参数中点法向 与 (点−轴心) 的单位向量点乘 | +1 → 凸（销/凸台）；−1 → 凹（孔/腔壁） |

例：件 7 F4 = 47.1/188.5 = 0.25 → R3 圆角；件 9 F6 = 75.4/75.4 = 1.00 且 dot=+1 → Ø4 销；
件 10 F5 = 657.5/657.5 = 1.00 且 dot=−1 → Ø52.3 沉孔壁。
只用"边界边是否相切"判圆角不成立：自动生成的 STEP 上切向边不可靠，且整圆柱也会被判成圆角
（件 9 那 4 个面就是这么错的，见 `docs/ANNOTATION-KAPPA.md` §4）。

`boss` 是本文扩的类（MFCAD++ 的合成件没有凸台）。到网关动作的映射：
`boss → cad.pocket`（按"岛"处理），`freeform → cad.pocket`（轮廓铣），
与 `instances.FAMILY_TO_ACTION` 一起维护，不另开一套。

## 3. 扩到更多件

流水线对件数没有假设。新件只要放进 `data/zenodo_rptu/` 并改 `build.py` 的 `parts` 列表，
前两步（几何 + 渲染 + 规则草稿）自动跑；人工只需看 `review.html` 里的八视图，
按 §2 的格式写 `overrides/<n>.json`。

按当前价格（件 8–10 的复杂度）估：**简单件 5 分钟、复杂件 15 分钟**，
主要时间花在"这个面是不是同一个特征的另一个壁面"这种拆合判断上。

## 4. 复核入口

`reports/annotation/review.html`（双击即可）：
每件一屏，左边八视图带面号，右边特征表（家族 / MFCAD 类 / 面号 / 判据），
折叠区是逐面高亮图。`需复核` 标签标出还没定死的件（当前是件 10）。
