### 1.2 三个研究问题

### 1.3 任务集与指标

- T1 几何问答 300 件 × 5 问；T2 建模复现 120 件；T3 工艺/G-code 300 件（自生成 + Mendeley 交叉验证）
- 指标：特征 macro-F1 ≥0.88、问答 ≥0.80、建模成功率 ≥75%、G-code 可执行率 ≥95%、
  无过切率 ≥90%、DFM 满足率 ≥85%、工具合法率 ≥98%、平均步数 ≤12、修复轮次 ≤2.1、
  单件 ≤40k token / ≤¥0.5 / ≤3min

### 1.4 基线与消融

四个基线：① 直接提示 LLM 生成 FreeCAD 脚本；② 纯文本 + LLM 规划（无工具）；
③ NumCraft 式多智能体（无几何验证）；④ GLLM 式参数抽取。
六项消融：−工具契约 / −分层摘要 / −验证闭环 / −DFM Critic / −记忆 / 单 vs 多智能体 / Qwen 7B-32B-Max。

### 2.3 计划外多做的东西

1. **区域掩码刀路**（几何上保证零过切的刀心可行域）——计划里只写"B 路受限 G-code"，没写算法。
2. **双线验收口径 + 四组实证**（过切/残留的物理不对称、栅格敏感性、边界带归因、细刀上界）。
3. **A 路负结果**（FreeCAD CAM 四种 BoundaryShape 都约束不住多级腔）。
4. **可复现脚手架**：数据集 sha256 冻结、`bench` 台账（重算/存档分离）、6 张主图脚本化。
5. **标注一致性研究**（30 面盲标 κ=0.751）+ 规则预标注基线（54.4%）。

## 4 为什么会偏

1. **自上而下是"能验证的先做"**：验证器、刀路、编排都能机械判对错，LLM 接入不能。
   于是每次遇到分叉，都选了"可判定"的那条——结果是工程越来越硬，科学主张越来越软。
2. **数据边界卡住了任务集**：只有 10 件带标注与参考 G-code，T1/T2 需要的 300/120 件
   得自建生成器，那是另一个工程。
3. **口径问题吃掉了大量时间**：过切/残留混算导致指标反复，最后做出 ADR-001 与四组实证——
   这部分是计划外的，但它确实是论文里最扎实的一段。

## 6 两条收口路线（需要你选）

### 路线 1：改题目，承认这是"可验证流水线"论文（成本 3–5 天）

- 标题去掉 LLM/Agent，改为 *Verification-Grounded Toolpath Generation for Multi-Level Pockets*
- 贡献改为：区域掩码刀路 + 双线验收 + 结构化错误与有界修复 + A 路负结果
- 砍掉 RQ1/RQ3、T1/T2、四个 LLM 基线，把"LLM 接入"写成 future work
- **优点**：现有证据全部支撑得住；**缺点**：与最初选题不一致，需你确认导师那边能接受

### 路线 2：补 LLM，把原计划救回来（成本 7–10 天）

- 按 A1→A2→A4→A7 顺序补：先接 LLM 做 Planner，再跑"自由脚本 vs 契约调用"对照，
  再加 token 统计与单/多智能体对照
- T1/T2 仍可暂缺（论文里限定在制造任务），但必须在 limitation 写清楚
- **优点**：保住原题目与 RQ；**缺点**：需要 API、需要重新跑实验、结论不确定

> 我的建议：**先做路线 1 的骨架（3 天，保证有一篇能投的稿），并行启动 A1**。
> 若 LLM 对照能出正向结果，再把题目改回 agent 叙事；出不来，路线 1 的稿子已经在了。
