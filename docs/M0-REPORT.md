**工序名已还原为真实工艺计划**（v1.2 新增能力）。以 10 号件为例：

```
PLANEN2 → 2D ADAPTIVE3 → 2D-KONTUR1 → 2D-TASCHE2 → 2D-KONTUR2
→ 2D ADAPTIVE5 → 2D-KONTUR3 → 2D ADAPTIVE7 → 2D ADAPTIVE6 → 2D-KONTUR4 → 2D-KONTUR6
```

`PLANEN`=面铣、`2D-TASCHE`=型腔、`2D-KONTUR`=轮廓、`2D ADAPTIVE`=自适应清料、`NUT`=槽。
**这是免费的工艺真值**：这 10 件不只是"STEP+G代码"，还自带专家用 Autodesk 后处理输出的
工序序列与命名，可直接作为 T3 轨道"工艺计划"的参考标签，无需额外标注。

**三条可用于论文的观察**

1. **结构复杂度单调，工序数单调，切削量不单调**：面数 10→33、工序 2→11 严格递增，可作难度分级；
   但切削长度 4.3k→30.2k mm 波动（4→5、7→8、9→10 均下降），**说明"切得多"≠"更复杂"**。
   论文里不能把切削长度当复杂度代理变量。
2. **上下文预算可核算**：L0 摘要每件约 120 token，L2 面表每 20 面约 600 token。
   最大件 33 面 → L0+L2 全量仅约 1100 token，4090 上 8K 上下文完全够用；
   但若把原始 STEP/AST 序列化（数万 token）则不可行 —— 这是 C2 的直接证据。
3. **空切比总体下降但非单调**：件 1 为 0.476，件 10 为 0.323，最低为件 7 的 0.145。
   趋势存在（复杂件路径更连贯），但波动说明它反映的是**刀具路径风格**而非复杂度，
   作为工艺质量对照指标需配合工序切换次数一起看。

## 4. 踩坑记录（已写入 `pitfalls.jsonl`）

1. **FreeCADCmd 执行脚本时 `__name__` 为文件名词干**，`if __name__ == "__main__"` 永不成立；
   且异常被吞、进程返回 0 —— 表现为"完全静默、无输出、无报错"。这是本次最大时间坑。
2. `Part.Vector` 不存在，向量类型在 `FreeCAD` 命名空间下。
3. FreeCADCmd 用 Boost program_options 解析 argv，脚本路径后的自定义参数会被当成它自己的选项。
