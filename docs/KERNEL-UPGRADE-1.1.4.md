# 几何内核升级报告：FreeCAD 0.20.1 → 1.1.4

> 日期：2026-11-04｜执行：自动安装 + A/B 回归｜结论：**通过，零偏差**

---

## 1. 为什么升级

| 维度 | 0.20.1（2022-08-10） | 1.1.4（2026-09-28） |
|---|---|---|
| 内置 Python | 3.8.10（2025-10 已 EOL） | **3.11.14** |
| OCCT 内核 | 7.5.x | 7.8.x |
| Path/CAM 工作台 | 缺自适应清角、部分精加工策略 | 完整 3 轴策略集 |
| 安全 | 存在已披露 CVE | 已修 |
| 语法/API | `Part.Vector` 缺失等历史包袱 | 与 1.x 一致 |

Python 3.8 EOL 是硬伤：后续想引入的依赖（pydantic v2、新版 numpy）随时会断供。

## 2. 安装方式与校验

用**官方便携包**而非 installer，三条理由：不写注册表、不需要管理员权限、**旧版可原样保留用于 A/B 对比**。

```
来源   https://github.com/FreeCAD/FreeCAD/releases/download/1.1.4/
       FreeCAD_1.1.4-Windows-x86_64-py311.7z        (398.7 MiB)
SHA256 4828741fc91ee37fafcdb97a1abacb18b04ba451ac4372d9ff7a7349b36f4d6d  ✅ 校验一致
落盘   E:\FreeCAD_1.1.4-Windows-x86_64-py311\      (2.3 GB, 38,816 个条目)
入口   bin\freecadcmd.exe（无头）  bin\freecad.exe（GUI）
```

**注意**：1.1.x 起可执行文件更名为小写 `freecadcmd.exe`；旧版是 `FreeCADCmd.exe`。Windows 不区分大小写所以不影响调用，但脚本与论文附录需按新名书写。

模块可用性实测：`Part` / `Import` / `Path` / `PathScripts` / `Mesh` / `Draft` / `PartDesign` / `Path.Main` 全部可导入。

## 3. 适配器同步改动

原实现硬编码 0.20.1 路径，且缓存键只含 STEP 内容 —— 换内核后会**静默命中旧内核的缓存**，产生看似成功的假结果。已修三处：

1. `_discover_cmd()`：`FREECAD_CMD` 环境变量优先；否则扫描 `E:/ D:/ C:/Program Files` 下 `FreeCAD*/bin/freecadcmd.exe`，按 mtime 取最新。便携版不写注册表，只能这样探测。
2. **缓存键 = SHA1(STEP 内容 | 内核版本 | 可执行名)**，内核一换自动失效。
3. 输出载荷新增 `engine: {cmd, version}`，每个几何结果都自带内核溯源信息 —— 论文实验日志需要这个字段。

### 4.1 归因：为什么重跑后的切削量和旧报告不同

换内核后重跑基线，切削长度出现明显变化（件 10：46848 → 21160 mm）。我没有直接接受这个数字，而是**用旧内核再跑一遍同一条链路**：

```
新内核 1.1.4 + parser v1.2  →  reports/m0_baseline.json
旧内核 0.20.1 + parser v1.2  →  reports/ab_oldkernel_newparser.json
两者零件数据逐字段相同：True（连浮点都相同）
```

结论：**差异与内核无关，全部来自 G 代码解析器的两处缺陷**（详见 `docs/M0-REPORT.md` 更正记录）：

| 缺陷 | 表现 | 修复 |
|---|---|---|
| 圆弧扫角未分顺逆时针 | 劣弧按优弧算，含圆弧零件切削长度虚高最多 2.2 倍 | v1.1：按 `arc_cw/arc_ccw` 定扫角方向 |
| 文件头注释被当工序名 | 工序表首行变成 `DESCRIPTION THIS MACHINE HAS...`，工序数虚高 1 | v1.2：按"首次换刀/首次运动"划文件头边界 + 丢弃零切削占位工序 |

这次排查顺手补上了两条工程保障，避免同类问题复发：

1. 报告强制携带 `meta{generated_at, kernel, parser}` —— 数据对不上时先看版本，不再靠回忆。
2. `ngc.PARSER_VERSION` 常量：**统计口径一变就必须递增并重跑基线**，写进模块注释。

副产品：v1.2 让解析器能还原真实工序名（`PLANEN2` / `2D-TASCHE2` / `NUT2` 等），
等于给锚点集免费加了"工艺计划"标签，直接可用于 T3 轨道的参考真值。

## 5. 行为差异与保留的坑

| 项 | 0.20.1 | 1.1.4 | 处理 |
|---|---|---|---|
| 可执行名 | `FreeCADCmd.exe` | `freecadcmd.exe` | 探测大小写无关，文档按新名 |
| 脚本 `__name__` | 文件名词干 | **相同**（实测 `NAME=[nm]`） | 保留原判定逻辑 |
| 异常处理 | 吞异常、exit 0 | **相同**（实测 raise 后 exit=0、无 traceback） | 必须保留 worker 内 try/except 写 JSON 兜底 |
| 脚本后 CLI 参数 | 被 Boost 解析劫持 | 未变（仍走环境变量） | 不变 |

**第 3 行是这次升级最重要的确认**：新版并没有修掉"静默失败"这个特性。如果当初没写兜底，今天换个内核就会重现"无输出、无报错、无产物"的三无故障。

## 6. 回滚方式

```bash
# 立刻切回旧内核，不改任何代码
export FREECAD_CMD="E:/FREECAD/bin/FreeCADCmd.exe"
```

彻底卸载：删除 `E:\FreeCAD_1.1.4-Windows-x86_64-py311\` 即可（便携版无注册表残留、无系统目录写入）。

## 7. 遗留事项

- **桌面快捷方式未创建**：本机安全策略禁止 COM 实例化（`WScript.Shell`），无法生成 `.lnk`。需要时手动右键 `E:\FreeCAD_1.1.4-Windows-x86_64-py311\bin\freecad.exe` → 发送到 → 桌面快捷方式。
- 旧版 `E:\FREECAD`（2.0GB）暂不删除，留作 A/B 对照与回滚；M1 结束、确认稳定后可清理。
- 首次启动 GUI 会有配置向导，属正常现象（不影响 `freecadcmd` 无头调用）。
