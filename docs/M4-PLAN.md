# M4 计划：多智能体编排

> 2026-11-05 起。上游：M3 已产出零过切刀路（B2）、结构化错误（`E_GOUGE` 带 `op_id/face_ids/by_op`）、
> 双线验收口径（ADR-001）。M4 消费这三样，把它们串成「失败 → 归因 → 定点修复 → 终审」的闭环。

---

## 1 目标与验收

| 项 | 内容 |
|---|---|
| 里程碑验收 | T3 子集端到端成功率 ≥ 60%（首轮） |
| 判据 | ADR-001 双线：最大过切 ≤0.5mm **且** 平均绝对偏差 ≤0.5mm；白名单零错误 |
| 交付 | 状态机、黑板、6 角色、有界修复、情节记忆，全部可测 |

## 2 任务集口径（与原计划的差异，必须先说清）

原计划写「T3 子集 20 件」。实际数据集 `data/zenodo_rptu/` 只有 **10 件**带 STEP、G-code 与
面级标注（`reports/annotation/geom/` 也是 10 件）。

**改为 10 件 × 2 种毛坯余量（1.0 / 2.5 mm）= 20 个任务**，并在报告里如实标注。
不拿「20 件」的说法去凑数——审稿人一对数据卡就会发现。

零件族由**目标高度层数**派生（不是零件号）：
`levels_le_2`（≤2 层，4 个任务）、`levels_3_4`（10 个）、`levels_ge_5`（6 个）。
族是记忆的检索键，必须能从几何算出来，否则换一件就失忆。

## 3 六个角色（职责与产物，禁止越界）

| 角色 | 读 | 写 | 干什么 |
|---|---|---|---|
| Analyst | `geom` / `labels` | `instances_obj` / `target` | 面→实例→目标高度图 |
| Planner | 实例 + 族记忆 | `plan` / `strategy` | 出工序计划（bbox 或 heightmap） |
| Emitter | `plan` | `gcode` / `emit_meta` | 后置处理成受限 G-code |
| Verifier | `gcode` / `target` | `metrics` / `errors` / `verdict` | dexel 仿真 + DFM，双线判 |
| Repairer | `errors` / `metrics` | `strategy` / `repair_action` | 定向修复，含「认输」 |
| Critic | `verdict` | `verdict_final` | 终审 + 写记忆 |

角色之间不互相调用，只经黑板上游键；每个角色只写自己的键。

## 4 有界修复的两档台阶

```
第 1 档 bbox        包围盒驱动，快，无区域掩码 → 多级腔必过切（M3 已证）
第 2 档 heightmap   目标高度层 L 的刀心可行域 = 对 {goal>L} 的柱按刀半径膨胀取补
                    → 几何上不可能切进材料
认输               第 2 档仍不合格 → 立刻 ESCALATE，带上 blocking 与错误对象
```

档数只有两档，所以真实数据上最多 1 轮修复就会收敛；`max_repair=3` 是**护栏**，
不是常态。为了证明护栏真的会拦，专门写了一条故障注入测试：把「安全规划器」
换成照样过切的实现，系统必须在第 2 轮认输，且 `rounds ≤ 3`。

## 5 记忆：按族检索，按签名留档

- 检索键 = 零件族（可预计算，跑之前就能查到）
- 留档字段 = 失败签名 `族|错误码`（审计用，不含零件号）
- 只复用**成功过**的修法；失败经验不当作建议

可测形式：冷启动 vs 热启动的**平均修复轮次**差。

## 7 不做

- 不接 LLM：M4 要证明的是**壳子**（状态机/黑板/有界/记忆）对，不是模型能力。换 LLM 放 M5。
- 不做并行/装夹分组：`depends_on` 已留出线性 DAG，等有装夹模型再说。
- 不为了让成功率好看而调阈值：口径与 M3 完全一致，0.5mm 不动。
