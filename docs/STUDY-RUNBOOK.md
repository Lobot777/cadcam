# 执行手册：4 人两轮怎么跑

> 人已招齐，这份是**照着做**的操作卡。设计依据在 `docs/STUDY-DESIGN.md`，
> 筛问卷/知情同意/逐字指导语在 `docs/STUDY-RECRUIT.md`，培训内容在 `docs/STUDY-TRAINING.md`。

**一句话流程**：D0 跑 T0（4 人，每人约 2 小时）→ 每人 20 分钟培训 → 间隔 ≥3 天 →
D+3 跑 T1（同样 186 题，题序洗过）→ 收 8 份 JSON → 一条命令出报告。

---

## 0 先认清三份页面

| 文件 | 什么时候给 | 是否含答案 |
|---|---|---|
| `reports/annotation/study/formal/annotate_T0.html` | T0 轮 | 否（页首判据提示也用 `--no-tips` 隐去） |
| `reports/annotation/study/formal/annotate_T1.html` | T1 轮 | 否，但页首有判据提示 |
| `reports/annotation/study/calib/calibration.html` | **只在培训环节、主试在场** | **是，20 题逐题给答案** |

T0 轮之前，受试者**不能**看到后两份页面，也不能看到培训手册。

`reports/annotation/study/responses/000_T0.json` 是今早生成的**演练模拟数据**
（带 `_simulation` 标记），不是真人作答；分析脚本会自动跳过，别删也别混进 P1–P4。
以 `_dryrun/` 开头的两个目录同样是流水线验证产物。

## 1 提前一天（30 分钟）

- [ ] 4 人已过筛问卷：`P1/P2` 熟练（不同单位）、`P3/P4` 零基础；互不相识；知情同意已签
- [ ] 编号 P1–P4 与姓名对照表**主试单独保存**，不进分析数据
- [ ] 设备统一：同一台电脑或同型号，Chrome / Edge，缩放 100%，关翻译插件与无关网页
- [ ] 把三份 HTML + 手册打印版分别放到各自的文件夹，**T0 页与 T1/校准页分开**
- [ ] 计时器、记录本（记提问原话）、劳务费（按小时，与准确率无关）
- [ ] 主试自己先打开 T0 页点两题，确认图片能加载、右上角编号能填、导出能触发
- [ ] **不要用无痕窗口**：页面靠 `localStorage` 存进度，无痕关掉后中途续标会全丢。
      用普通窗口即可，4 人靠各自的编号隔离（键是 `编号:轮次`），不需要清缓存。

## 2 排期（用相对日，照抄即可）

| | D0 | D+1 | D+3 | D+4 |
|---|---|---|---|---|
| P1 | T0 上午 → 培训 | | T1 上午 | |
| P2 | T0 下午 → 培训 | | T1 下午 | |
| P3 | | T0 上午 → 培训 | | T1 上午 |
| P4 | | T0 下午 → 培训 | | T1 下午 |

四条硬约束：

1. **独立场次**：不建群、不重叠、不互相看见屏幕；熟练两人本来就是不同单位。
2. **T0→T1 恰好 3 天以上**，且**时段一致**（上午对上午、下午对下午）。
3. 每轮分 **3 段：70 / 70 / 46 题**，段间强制休息 ≥10 分钟。
4. 两轮的**指导语逐字一致**，设备、浏览器、亮度、休息规则都不变。

如果 4 人凑不齐同一天，顺延即可，但每人的 T0→T1 间隔与时段必须各自保持一致。

## 3 T0 轮：逐分钟操作卡（每人一份）

| 时刻 | 主试做什么 | 注意 |
|---|---|---|
| −5 min | 用**普通窗口**打开 `annotate_T0.html` → 右上角填编号（如 `P1`） | 确认顶栏 `0 / 186`；进度按「编号+轮次」分开存，换人只要改编号，数据天然隔离 |
| 0 min | **逐字念指导语**（下方方框） | 不解释类别、不举例、不提示判据 |
| 0–70 题 | 静默监考 | 只答操作问题；把受试者的提问**原话**记下来（这是定性数据） |
| 第 70 题后 | 休息 10 分钟，记时间 | |
| 70–140 题 | 第 2 段 | |
| 第 140 题后 | 休息 10 分钟 | |
| 140–186 题 | 第 3 段（46 题） | |
| 结束 | 点右上「导出 JSON」 | 确认 `count = 186`；改名 `P1_T0.json` 存 `responses/` |
| 收尾 | 记录总耗时、休息次数、主观感受一两句 | **不给任何对错反馈、不透露答案** |

**逐字指导语（两轮一字不改）**

> 这个任务是给零件上高亮的那个面选一个类别。页面上方有九类速查表，可以随时点开看。
> 每张图旁边列了这个面的面积、法向、位置、邻面，这些都是测出来的数，怎么用你自己决定。
> **判不出来就点「判不了」，这是合法答案，不算错、不扣分。**
> 选完可以顺手点一下「确定 / 拿不准 / 猜的」，这个也不影响结果。
> 请按从上到下的顺序做，不要跳，不要回头改。每做 70 题我会叫你休息 10 分钟。
> 中间有任何操作上的问题可以问我。

## 4 培训：T0 之后立刻，20 分钟/人

按 `docs/STUDY-TRAINING.md` 的主试流程表：

| 时间 | 内容 |
|---|---|
| 0–3 min | 发手册，念九类定义，**先讲规则 0**（按特征归类不按面型；本批只有 7 类；6 个 BSpline 面归 boss） |
| 3–8 min | 三条判据（弧段占比 / 径向点积 / 邻面法向+z），重点是 ①×② 组合决策表；带受试者把 5 个例题自己算一遍 |
| 8–10 min | 六个常见错与 ⚠️（凹不等于孔、别自己算点积、别选 freeform）；重申「判不了」合法 |
| 10–20 min | 打开 `calib/calibration.html`，20 题当场点、当场看答案和解释 |

**纪律**：校准页明文含答案，只在主试在场时打开，不许拷走；答错不锁定可重做；
顶栏「首次答对」只是培训记录，**不进 κ 分析**。可导出 `P1_calibration.json` 存档（可选）。
**培训当天不要重标正式题**，T1 至少隔 3 天。

## 5 T1 轮：与 T0 完全相同，只换三处

1. 页面换成 `annotate_T1.html`（含判据提示、题序洗过，**题目仍是同样 186 道**）
2. 培训手册放在受试者手边，允许随时查
3. 右上角编号不变（如仍是 `P1`），但轮次标记不同，localStorage 键自带 round，**不会覆盖 T0**

其余全不改：逐字指导语、3 段休息、设备、时段、监考规则。导出 `P1_T1.json`。

> 两轮题集完全一致才能做逐题配对的 McNemar 检验。别因为「怕他记住」而换题。

## 7 出结果：一条命令

```bash
cd E:/CAD2CAM
python scripts/annotate/kappa_study.py                 # 收齐 8 份后
python scripts/annotate/kappa_study.py --boot 500      # 边收边看的快速预演
```

产出 `reports/annotation/study/results/`：

| 文件 | 内容 |
|---|---|
| `REPORT.md` | 人读报告（κ 表、分家族、难题子集、培训前后、质控） |
| `summary.json` | 全部数字，机器可读 |
| `ai_rule.json` | autolabel 规则 v2 的独立算法基线标签（同时给出它与真值的逐题一致率） |

脚本会：自动跳过 `000_*` 演练数据与 `*_eval.json`；同轮不足 2 人时明确提示"数据不足"
并照常输出单人描述统计，所以**边收边跑不会报错**。

报告里对应设计文档 §7 的每一项：

- 平均两两 Cohen κ + 题级 bootstrap 95% CI、仅作答题 κ、二值 `stock`/非 stock κ
- 分家族 κ（只报 ≥15 题的 5 类）、15 个难题子集 vs 常规子集
- 每人准确率 / 判不了率 / **体系外误选率**（`freeform` / `chamfer`）/ 耗时中位数 / `<5s` 题数
- 培训前后：Δ准确率 + McNemar χ²（>3.84 视为显著）
- 人-真值 κ 与 人-规则基线 κ
- 质控段：完成率、`<5s` 乱点、`order × 判错` 的疲劳相关 ρ、逐份「通过/作废」判定

> **口径提醒**：`ai_rule.json` 是纯规则 v2 的输出，**不是**裁决后真值
> （真值是 `formal/key.json`）。论文里"AI 是否落在人类一致性带内"用前者做比较，
> 两者不要混称。初稿若把规则基线说成"AI 主标"，会被审稿人挑。

**已用 8 份模拟数据端到端验证过**：4 人 186 题时平均 κ 的 CI 半宽约 0.055，
与设计文档预测的 ±0.049~0.056 吻合。演练数据不体现培训增益，别拿它预判真人结果。

## 8 异常处理

| 情况 | 处理 |
|---|---|
| 页面打不开 / 图不加载 | 换 Chrome 或 Edge；单文件 3.4 MB，首次加载 3–5 秒；**别用微信内置浏览器** |
| 中途有事要走 | 进度自动存在 `localStorage`，**同一浏览器普通窗口**回来接着标；记录中断时长与题号。别关无痕窗口、别换设备 |
| 导出条数 < 186 | 回页面补完再导出，记缺题数，不手改 |
| 问「这题该选什么」 | 只答「请按你的判断，判不准可以点判不了」，把提问原话记下来 |
| 想查手机 / 与他人讨论 | 制止；该场次记入备注，必要时作废 |
| 误把 T1 页/校准页给了 T0 | 该份作废，清 localStorage 后重标，并在记录里写明 |
| 有人退出只剩 3 人 | 可继续，κ 半宽 ±0.049 → ±0.056；报告里写明人数 |
| 两轮时段无法一致 | 记进元数据表当协变量，**不要**为此改指导语 |
| 受试者说某题看不清高亮 | 记录题号；红绿色觉问题见 `STUDY-RECRUIT.md` §7 |

## 10 现在就能做的第一件事

让 P1 先跑 T0 的**前 20 题**，掐表算真实每题耗时，用它替换设计里的「~35 s/题」假设：

- 若中位数 ≤ 45 s → 按 3 段（70/70/46）执行，每轮约 2 小时

这一步只花 15 分钟，能避免 4 个人全部排错时间。确认后再正式开始 T0。
