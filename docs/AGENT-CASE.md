# agent 叙事还能不能成立：把证据摆在一张桌上

> 2026-11-06（B9、跨模型、云端对照之后第三次重写）。基于 M4（确定性编排）与 M5
> （15 个模型：5 个本地量化 + 10 个云端，六个实验）。
> **结论：能成立，但要换个立足点——不是"模型会算"，而是"模型会听懂、系统会兜住"。**
> B9 之前我的判断是"只能站在验证上"，现在有正面数据：自然语言 → 契约调用 20/20，
> 特征去除体积 IoU 0.985。差别在于**让模型做语言，不让它做几何**。

---

## 1 支持 agent 的证据（五条，都有数）

| 能力 | 证据 | 出处 |
|---|---|---|
| **语言 → 动作（核心）** | 20 条中文工单：执行 20/20、调用合法率 1.000、**特征去除体积 IoU 0.985** | `reports/m5_nl_eval.json` |
| **语言的鲁棒性** | 8 条难工单（"正中央"/"左上角"/"1.5 cm"/"四角"）：8/8 执行、去除 IoU 0.768、6/8 ≥0.9 | 同上 |
| **受控动作空间** | 13/13 事务回放、7 类错误 100% 拦截、失败零副作用 | `reports/m1_acceptance.json` |
| **闭环自纠** | 首轮过切 18/20，全部被有界修复救回；修复 ≤1 轮 | `reports/m4_run.json` |
| **记忆** | 平均修复轮次 0.90（冷）→ 0.15（热），−83% | `reports/m4_run.json` |
| **多轮修复（有边界）** | 10 条难工单：9/10 在 ≤2 轮内解决（R7 第二轮修好） | `reports/m5_repair_eval.json` |
| **跨 15 个模型稳定** | 合法率 **15/15 都是 1.000**；云端旗舰 30 题零误差（IoU 1.000） | `docs/M5-MODELS.md`、`docs/M5-CLOUD.md` |
| **会追问** | 欠约束工单：云端追问质量 **6.8/8**，本地 **0.8/8**（两个 0/8） | `docs/M5-AMBIGUITY.md` |
| **契约可扩展** | 新增斜底槽特征只改 30 行几何 + 1 条 spec，dexel/高度图/评测管线**零改动** | `docs/M5-RAMP.md` |

这几条合起来是一个**完整的 agent 定义**：听懂需求 → 在受控动作空间里执行 →
失败能判、能改、能记。而且这不是"某个模型碰巧行"：换成 15 个不同厂商/规模的模型，
契约层的合法率**一条没变**。

## 2 反对 agent 的证据（四条，也都留着）

| 主张 | 实测 | 出处 |
|---|---|---|
| 模型能直接写 G-code | **0/10 通过**；8/10 语法合法但几何全错，最深切穿 48 mm | `reports/m5_direct_eval.json` |
| 模型能写建模脚本 | 执行 19/20，但**特征去除体积 IoU 只有 0.17**（毛坯对、切的地方错） | `reports/m5_nl_eval.json` |
| 模型能做双目标权衡 | 一句成本提示让 **20/20** 决策整体翻转，无一次按层数分化 | `reports/m5_llm_eval.json` |
| 模型能读懂结构化错误 | 本地 8B 上三组行为**逐项相同**；但云端 mimo **1/4→4/4**、glm-5.3 **2/4→4/4** | `reports/m5_llm_eval.json`、`reports/m5_cloud_compare.json` |
| 模型能消除需求歧义 | H06（"关于 y=50 对称"未给距离）**8/9 个云端模型读错**，无一追问 | `reports/m5_cloud_compare.json` |
| 模型能同时满足多个空间约束 | 第二套 20 条里云端只在 6 条出错，但**3/10 错在 E06**（居中 + 留缝 5）、2/10 错在 E14（位置链） | `docs/M5-HARD2.md` |

**两边并不矛盾**：模型的语言能力是真的，几何能力是假的。
所有"反对"都指向同一个结论——**别让它碰几何，让它碰意图**。

修复这一条要补两句边界（都是跨模型之后才看清的）：

1. **反馈能修"漏做/算错"，修不了"理解错"**（本地 8B）。R7 第二轮就修好了（漏了四角孔）；
   R1 给三轮、给到"该处仍有余料"都修不动，一说"应在中心 (15,65)"立刻 3/3 对。
2. **但"修不动"这件事本身随模型能力移动**：同一份错误起点，云端 mimo 从 vague 1/4
   提升到 structured **4/4**，glm-5.3 从 2/4 到 **4/4**。所以不是"反馈无用"，
   而是**结构化反馈的价值需要足够的指令跟随能力才能兑现**。

补上"追问"这一环之后，agent 定义更完整了：**听懂 → 不确定就问 → 执行 → 失败能判能改能记**。
但这一环的落差也最大：云端 7/10 拿到 4/4，本地 5 个里最好 2/4、两个 0/4。

还有一条更硬的边界：**15 个模型的合法率都是 1.000，却没有一个能保证"意图正确"**。
H06 那条题 8/9 个云端模型都读成别的合理布局，**没有一个追问"距中线多远"**。
这说明契约层能保证"可执行、可校验、可回滚"，**不能替代需求澄清**——
真要补这一环，得让 agent 会"问"，而不是会"猜"。

## 3 三条可辩护的写法（按推荐度）

### A′. 语言前端 + 契约执行 + 验证兜底（**推荐**）

> 主张：**agent 的能力边界由"动作空间"决定，不由模型规模决定。**
> 在封闭动作空间里，8B 模型的语言理解足以驱动完整的建模流程；
> 一旦放开生成，同一模型立刻崩掉。

- 正面证据：B9 的 20/20、IoU 0.985；难工单 0.768；15 个模型合法率恒 1.000
- 反面证据：B7 的 0/10 与 0.17——**同一模型、同一批零件**，只换了动作空间
- 边界证据：H06 说明"意图歧义"是契约层管不到的，需要澄清而非执行
- 这两条放在一起，就是一张"为什么需要契约"的对照表，比任何论证都硬
- 标题建议：*Language-Grounded, Verification-Bounded: A Contract-Based Agent for CAD/CAM*

### B. 纯验证论文（去掉 agent 叙事）

只讲区域掩码 + 双线口径 + 有界修复，LLM 降为附录。M3/M4 的证据足够撑一篇，
但与选题脱节，且丢掉 B9 这个最漂亮的结果。

### C. 端到端大模型 agent（不推荐）

需要 LLM 直接生成几何并通过验证——B7 已经证明 8B 做不到，换 70B 也只是概率问题，
而且审稿人会问"那你的验证器还有什么用"。

## 4 还没补的口子（诚实清单）

| 缺口 | 影响 | 补法 |
|---|---|---|
| **工具集覆盖** | 20 条工单是从工具 schema 反推生成的，**天然可表达**；这是循环论证的风险 | 用真实图纸/工单（含圆角、斜面、非轴向特征）再测一轮，预期会掉 |
| **难工单只有 8 条** | 0.768 的置信区间很宽 | 扩到 30–50 条 |
| **单模型单次** | 只有 Qwen3-8B、temperature=0、单次运行；easy/script 两次跑出 19/20 与 16/20，方差不可忽略 | 加 2 个模型 + 3 次重复，报均值与区间 |
| ~~没有多轮修复~~ **已补** | 9/10 在 ≤2 轮解决；语义误读修不动（见 §2） | 见 `reports/m5_repair_eval.json` |
| **没有人的基线** | 不知道人类编程员做同样工单要多久、错多少 | 1–2 名工程师做 10 条，记时间与 IoU |

## 5 建议的下一步顺序

1. ~~补多轮修复~~ **已完成**：10 条难工单 9/10 在 ≤2 轮解决；语义误读修不动（见 §2）。
   顺带得到一条更硬的结论——**修复有效性取决于错误类型**，不是"有反馈就能自纠"。
2. **扩难工单到 30 条 + 两组重复**（1 天）：现在 0.768 与 9/10 的区间都太宽，
   尤其 easy/script 两次跑出 19/20 与 16/20，方差必须报出来。
3. **换一个模型对照**（半天，可选）：llama3.1:8b 或 qwen3:14b，看语言能力是否可替换。
   若换大模型后 R1 能自己修对，这条就从"模型限制"变成"规模限制"，结论要改写。
4. **真实图纸**（1–2 天，可选）：找 5–10 张带圆角/斜面的图，测工具集覆盖率的真实上限。
5. **人的基线**（1 天，可选）：1–2 名编程员做同样 10 条工单，记时间与 IoU。
   没有这个，"20/20 到底算不算好"只能靠感觉。

> 一句话：**证据已经够支撑"语言前端 + 契约 + 验证"这个 agent 故事；
> 但"工具集能表达多少真实工单"和"换个模型会不会翻盘"是审稿人一定会戳的两处，越早补越好。**
