# M2 报告：MFCAD++ 面级加工特征识别

> 日期：2026-11-04｜里程碑：M2（空间模态）｜状态：完成并通过验收（10/10）
> 环境：FreeCAD 1.1.4 + PyTorch 2.6.0/cu124 + RTX 4090

## 0. 一句话结论

在 MFCAD++ 留出 test 上，面级准确率 **96.60%**、mIoU **90.42%**（0.35M 参数，训练 147 秒），
超过同特征集上的梯度提升树基线 **4.4 个百分点**；但**零样本迁移到真实零件时语义明显失准**，
靠几何判据交叉校验兜住了最危险的一类错误（把外轮廓圆角判成孔）。

---

## 1. 先纠正一个前提

任务原话是「接 MFCAD++ 预训练模型」，但**MFCAD++ 没有官方预训练权重**——
它只发布数据集（59,665 个 STEP，1.5 GB，CC BY）。公开的权重来自 AAGNet 等第三方，
绑定 pythonocc-core 7.5.1 + DGL 的特定版本，且在百度 AI Studio 后面。

所以走的是「用 MFCAD++ 自己训」。这在论文里反而是更好的选择：可控、可复现、
能报告训练成本（147 秒 / 0.35M 参数），而不是引用一个黑盒权重。

| 项 | 事实 |
|---|---|
| 数据集 | MFCAD++，59,665 件 STEP（train 41,766 / val 8,950 / test 8,949） |
| 标签 | 每面一个类别号 0–24，写在 STEP 的 `ADVANCED_FACE('N',...)` 里 |
| 标签粒度 | **语义分割**，不是实例分割——只知道"这个面属于哪类特征"，不知道"哪些面属于同一个特征" |
| 本次用量 | train 7,998 件 / 239,520 面；val 1,500 / 45,003；test 1,998 / 60,210 |

最后一行是必须写进论文局限的：**MFCAD++ 无法支撑实例级评测**。
工艺规划需要"三个 Ø6 孔 = 三道工序"，而这需要实例标签（MFInstSeg / AAGNet 才有）。

## 2. 做完了什么

| # | 产出 | 位置 |
|---|---|---|
| 1 | STEP 标签解析器（纯文本，不经 OCC） | `src/cadcam/modalities/brep/step_labels.py` |
| 2 | AAG 构建器：面为节点、邻接为边、18 维节点特征 + 4 维边特征 | `src/cadcam/modalities/mfr/aag.py` |
| 3 | 三层 GraphSAGE（纯 PyTorch，不依赖 PyG） | `src/cadcam/modalities/mfr/model.py` |
| 4 | 并行数据管道（18 进程，16.3 件/秒） | `scripts/extract_mfcad.py` |
| 5 | 面级预测 → 特征实例聚合 | `src/cadcam/modalities/mfr/instances.py` |
| 6 | 几何判据交叉校验 | `src/cadcam/modalities/mfr/verify.py` |
| 7 | 网关新工具 `feature.recognize` | `src/cadcam/gateway/tools.py` |
| 8 | 训练 / 评测 / 基线 / 验收脚本 | `scripts/{train_mfr,eval_mfr,baseline_mfr_sklearn,m2_demo}.py` |

**面顺序对齐**是个必须先钉死的前提：如果能按索引对标签，标签就是免费的；
不能就必须做几何匹配，而几何匹配在同面积面上必然歧义（立方体六个面两两相等）。
实测 **40/40 件 surface 类型序列逐位相同**，可以直接按索引对齐。

## 3. 三档结果（同一 test 集，1998 件 / 60,210 面）

| 方法 | 用到的信息 | 面级准确率 | mIoU | 参数 |
|---|---|---:|---:|---:|
| 逐面 MLP（消融：摘掉所有边） | 仅面自身特征 | 69.69% | 44.62% | 0.35M |
| 梯度提升树 | 面特征 + 手工 1 跳邻域统计（85 维） | 92.24% | 77.05% | — |
| **GraphSAGE ×3** | 面特征 + 可学习多跳消息传递 | **96.60%** | **90.42%** | **0.35M** |

三档构成完整的论证链：**只看面本身不够（69.7%）→ 邻域信息关键（+22.6pt）→ 可学习的多跳聚合再涨 4.4pt**。
如果只报 GNN 一个数，读者无法判断增益来自架构还是特征；有了消融才能说清。

文献对照：Hierarchical CADNet 97.37%（41,766 件全量训练），AAGNet 99.57%。
我们用 19% 的训练数据达到 96.60%，差距主要来自训练集规模和网络容量，不是结构缺陷。

### 逐类表现（GNN，按 IoU 升序）

| 类别 | 支持数 | GNN IoU | 树基线 IoU | Δ |
|---|---:|---:|---:|---:|
| rectangular_through_step | 1,502 | 0.581 | 0.543 | +0.04 |
| slanted_through_step | 1,619 | 0.612 | **0.706** | **−0.09** |
| rectangular_through_slot | 923 | 0.722 | 0.320 | **+0.40** |
| triangular_through_slot | 569 | 0.817 | 0.647 | +0.17 |
| rectangular_blind_slot | 720 | 0.842 | 0.444 | **+0.40** |
| round | 260 | 0.926 | 0.524 | +0.40 |
| through_hole | 913 | 0.965 | 0.739 | +0.23 |
| stock | 13,461 | 0.991 | 0.947 | +0.04 |
| 其余 17 类 | — | 0.91–0.99 | 0.77–0.97 | +0.02–0.16 |

**GNN 在 24/25 类上不低于基线，唯一落后的是斜向贯穿台阶（−0.09）。**

## 4. 三个值得写进论文的发现

### 4.1 槽类靠的是全局拓扑，不是局部几何

最弱的两个基线类别正是两种槽（IoU 0.32 / 0.44），GNN 把它们拉到 0.72 / 0.84。
原因很清楚：**槽和型腔的壁面在局部几何上完全一样**，区别在于"槽是否贯穿到零件边界"——
这是一个需要多跳才能传到的全局属性。两层消息传递之后，壁面节点才能"看到"零件外轮廓。

这直接支撑 C2 的一个副产品论点：特征识别不能只喂局部几何，
**必须让模型能看到零件的整体拓扑**，这与"渐进式几何披露"是同一个设计原则的两面。

### 4.2 台阶类内部本就模糊

扣分集中在三类台阶之间（rectangular 0.581 / slanted 0.612 / 2sides 0.917）。
这不是模型缺陷，是**标注本身的可分性问题**：三者都是"把零件一侧削掉一层"，
差别只在被削面的走向。人工标注时同类边界也会摇摆。

论文里应把这作为"标签噪声"讨论，而不是掩盖。

### 4.3 显式凹凸特征对树模型有用，对 GNN 冗余

加了两维「面周边凹边比 / 凸边比」后：

| | 加特征前 | 加特征后 | Δ |
|---|---:|---:|---:|
| 树基线 | 90.95% / 72.06% | **92.24% / 77.05%** | +1.3 / +5.0 |
| GNN | 96.82% / 90.99% | 96.60% / 90.42% | −0.2 / −0.6 |

树模型受益明显（它只能看固定的 1 跳统计，补上这个信号直接有用），
GNN 反而略降（噪声范围内）。合理解释是**图消息传递本身就能从邻边推出凹凸**，
显式喂进去是冗余信息，加了只是多两个维度。

这个观察有个方法论意义：**特征工程与架构能力是替代关系，不是叠加关系**。
声称"我们加了 X 特征所以更好"之前，应该先测这个特征对更强架构是否还有边际价值。

## 5. 必须承认的失败：零样本迁移

真实零件（Zenodo 锚点集，80×80×50 铝块，真实 CAM 输出）从未参与训练。直接推理的结果：

**9 号件（真值：4 个 Ø4 孔 + 四角 R5 圆角 + R37.5 外轮廓）**

```
模型输出：stock ×6；chamfer ×4；hole ×6（Ø10）；groove ×1（Ø4）
平均置信度 0.967，低置信度面占比 0.000
```

**它把 4 个外轮廓圆角判成了 Ø10 孔，而且置信度 96.7%、没有一张脸是"不确定"的。**

这比准确率低更危险：如果按置信度决定要不要复核，这类错误会被直接放行。
域偏移的原因是可查的：MFCAD++ 是 10–50mm 的合成件，`round` 类只出现在棱边，
而 Zenodo 的 R5 是 80mm 件的外轮廓圆角；此外真实件含 BSpline 自由曲面，
MFCAD++ 里根本没有这个面类型。

### 应对：不信任模型自证，用几何判据否证

圆柱面是孔壁还是凸台，由**法向与径向的点积符号**唯一确定（M1 已验证）。
加一层 `verify.cross_check`，冲突时以几何为准：

```
9 号件纠正后：stock ×6；chamfer ×4；boss_or_fillet ×4（Ø10）；hole ×3；groove ×1（Ø4）
                                   ^^^^^^^^^^^^^^^^^^^^ 4 处冲突全部纠正
```

这条正好是论文 C3「验证接地的闭环」的实例：**不是让模型自证，而是用可独立计算的
物理量去否证它**。也说明架构上必须保留"模型 + 规则"双通道，不能纯端到端。

仍未解决：4 个 Ø4 孔被拆成 3 个 hole + 1 个 groove，语义仍不准。
数量（4）和直径（Ø4）对了，类别名错了——对下游工艺影响有限（都走钻孔），但不能算对。

## 6. 模型与成本

| 项 | 值 |
|---|---|
| 结构 | 3 层 GraphSAGE，hidden 256，边特征参与消息 |
| 参数 | 0.35M（AAGNet 0.38M，量级相当） |
| 训练 | 40 epoch / 147 秒 / RTX 4090（8000 件） |
| 数据抽取 | 16.3 件/秒（18 进程），8000 件约 8 分钟 |
| 单次推理 | 单件 < 10 ms |

**训练成本低到可以当"实验参数"而不是"工程投入"**：换一版特征重训只要 2.5 分钟，
这意味着论文里的消融可以做得比常规更密。

## 7. 已知缺陷

1. **无实例标签**。MFCAD++ 只有语义分割，实例聚合靠"同标签 + 连通分量"近似，
   相交特征会粘连。9 号件的 4 个孔被拆成 3+1 就是例子。
2. **域偏移未经量化**。真实件没有面级真值，只能定性核对；定量需要人工标注 10 件锚点集（约 320 面）。
3. **台阶三类混淆**是主要误差源，占错误的大头。
4. **BSpline 面**在训练集中不存在，真实件上必然误判（9 号件有 4 个）。

## 9. 复现

```bash
# 1. 抽取数据（需要 MFCAD_dataset.zip）
python scripts/extract_mfcad.py --split train --limit 8000 --workers 18
python scripts/extract_mfcad.py --split val   --limit 1500 --workers 18
python scripts/extract_mfcad.py --split test  --limit 2000 --workers 18

# 2. 训练（conda env: cadcam，需 torch）
python scripts/train_mfr.py --epochs 40 --hidden 256 --out reports/mfr_train_v2.json

# 3. 评测（test 集）
python scripts/eval_mfr.py --weights reports/mfr_train_v2.pt --out reports/mfr_test_v2.json

# 4. 对照组
python scripts/baseline_mfr_sklearn.py --max-iter 250 --out reports/mfr_baseline_v2.json

# 5. 验收
python scripts/m2_demo.py
```
